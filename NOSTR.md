# Использование сторонних Nostr-клиентов с Buzz

Buzz — это Nostr-релей, нативно поддерживающий стандарт NIP-29 (группы на базе релея). Любые сторонние клиенты Nostr могут подключаться напрямую к `buzz-relay`, используя протоколы NIP-29 и аутентификацию NIP-42.

## Границы сообщества (Community scope)

Buzz рассматривает URL/домен релея как авторитетный источник для сообщества. В текущей конфигурации с одним релеем за URL закреплено ровно одно сообщество, поэтому существующие клиенты NIP-29 продолжают использовать те же WebSocket URL, типы событий, теги и пути HTTP/media/git. В мультиарендной конфигурации каждое сообщество доступно по собственному домену или поддомену.

Формат передачи Nostr не обрастает лишними тегами арендатора. Теги `#h`, передаваемые клиентом, по-прежнему обозначают каналы/группы и проверяются на принадлежность к сообществу текущего хоста. События без тега `#h` (профили, подарочные DM NIP-17, списки, уведомления) глобальны только внутри подключенного сообщества.

## Прямое подключение по NIP-29

Подключайте любой клиент с поддержкой NIP-29 прямо к релею.

### Быстрый старт

```bash
# 1. (Опционально) Включить белый список публичных ключей (до запуска релея)
export BUZZ_PUBKEY_ALLOWLIST=true

# 2. Запустить релей (автоматически поднимет Docker и применит миграции)
just relay &                         # релей доступен на :3000

# 3. Добавить публичный ключ в белый список (если включен)
PGPASSWORD=buzz_dev psql -h localhost -U buzz -d buzz -c \
  "INSERT INTO pubkey_allowlist (pubkey) VALUES (decode('<64-символьный-hex-pubkey>', 'hex'))"

# 4. Подключить любой NIP-29 + NIP-42 клиент к ws://localhost:3000
```

### Что работает

| Возможность | Статус | Примечания |
|---|:---:|---|
| **Групповой чат (kind:9)** | ✅ | Отправка и прием сообщений с тегом `#h <channel-uuid>` |
| **Реакции (kind:7)** | ✅ | Стандарт NIP-25; канал определяется по тегу `#e` целевого события |
| **Удаление сообщений (kind:5)** | ✅ | Стандарт NIP-09; только собственные сообщения. Тег `#e` обязателен |
| **Профили пользователей (kind:0)** | ✅ | Метаданные NIP-01; синхронизируются в таблицу `users` (display_name, avatar, about, NIP-05) |
| **Создание группы (kind:9007)** | ✅ | NIP-29; тег `name`, опционально `visibility` и `channel_type` |
| **Добавление пользователя (kind:9000)** | ✅ | Открытые каналы: любой пользователь. Приватные: только владелец/админ |
| **Удаление пользователя (kind:9001)** | ✅ | Самостоятельный выход или удаление администратором |
| **Редактирование метаданных (kind:9002)** | ✅ | Теги `name`/`about`: админы; теги `topic`/`purpose`: любой участник |
| **Удаление группы (kind:9008)** | ✅ | Только владелец |
| **Выход из группы (kind:9022)** | ✅ | Любой участник (с защитой от удаления последнего владельца) |
| **Метаданные группы (kind:39000)** | ✅ | Подписываются релеем: теги `d`, `name`, `closed`, `private`, `hidden` |
| **Администраторы группы (kind:39001)**| ✅ | Подписываются релеем; тег `d` + теги `p` с ролями (`owner`, `admin`) |
| **Участники группы (kind:39002)** | ✅ | Подписываются релеем; тег `d` + теги `p` для всех участников |
| **Уведомления о членстве** | ✅ | kind:44100 (добавлен) / kind:44101 (удален) |
| **Присутствие (kind:20001)** | ✅ | Эфемерные статусы, сохраняются в Redis на 180 сек и рассылаются подписчикам |
| **Индикаторы набора текста (kind:20002)**| ✅ | Эфемерные, транслируются через Redis pub/sub |
| **Аутентификация NIP-42** | ✅ | Проактивный челлендж со стороны релея |
| **Информация о релее NIP-11** | ✅ | Запрос `GET /` с заголовком `Accept: application/nostr+json` |
| **Медиафайлы Blossom** | ✅ | Загрузка `PUT /media/upload` (BUD-02), отдача `GET /media/{sha256}.{ext}` (BUD-01) |
| **Поиск NIP-50** | ✅ | Однократные запросы поиска REQ: `{"search":"запрос","kinds":[9],"#h":["<uuid>"]}` |
| **Ветки обсуждений NIP-10** | ✅ | Ответы с тегами `["e","<root>","","reply"]` атомарно создают метаданные тредов |
| **Личные сообщения NIP-17 (gift wrap)**| ✅ | Принимаются события kind:1059 с эфемерными ключами подписи |

### Что пока не поддерживается

| Возможность | Статус | Причина |
|---|:---:|---|
| **Создание инвайтов (kind:9009)** | ⚠️ | Принимается и сохраняется, но обработчик отложен |
| **Роли групп (kind:39003)** | ❌ | Определены в реестре kind, но не генерируются релеем |
| **Старые форматы DM** | ⚠️ | Поддерживаются только gift wrap NIP-17; NIP-04/NIP-44 не реализованы |

### Белый список публичных ключей (Pubkey Allowlist)

При установке `BUZZ_PUBKEY_ALLOWLIST=true` подключения по NIP-42, авторизующиеся только по pubkey (без API-токена), сверяются с таблицей `pubkey_allowlist`. Это позволяет открыть доступ к релею конкретным внешним идентичностям Nostr.
