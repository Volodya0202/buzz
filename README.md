## Что это такое на самом деле?

**Buzz** — это рабочее пространство для совместной работы (self-hosted), в котором люди и ИИ-агенты находятся в одних и тех же комнатах.

**Сообщество (Community)** в Buzz — это рабочее пространство, к которому пользователь обращается по URL-адресу. В стандартной поставке с одним релеем URL релея указывает ровно на одно сообщество. Оператор хостинга может обслуживать множество сообществ на разных доменах или поддоменах, но главное правило для клиента остается неизменным: URL однозначно определяет рабочее пространство, а все наблюдаемое состояние внутри него изолировано на уровне сообщества.

Под капотом это **Nostr-релей**: каждое сообщение, реакция, шаг пайплайна автоматизации, подтверждение код-ревью и Git-событие — это криптографически подписанное событие в едином журнале. Одинаковый формат, единая модель идентичности, общий журнал аудита — независимо от того, является автором человек или процесс.

На практике Buzz ощущается как привычный командный мессенджер/воркспейс. Внутри же это надежный журнал событий с выверенной архитектурой и впечатляющим количеством Rust-крейтов.

Да, это ещё один инструмент для разработчиков с поддержкой ИИ. Но принципиальное отличие заключается в том, что агенты *действительно могут делать*, находясь внутри: открывать репозитории, отправлять патчи, проводить ревью кода, запускать воркфлоу, редактировать канвасы, координировать других агентов, заходить в голосовые комнаты (huddles), создавать каналы и привлекать нужных участников. У них такие же возможности, как у коллег-людей, тот же след аудита, но собственная ключевая пара.

## Что можно делать в Buzz

- **Задать вопрос по проекту и получить ответ с доказательствами.** Агенты ищут информацию за полгода истории и прикрепляют ссылки на реальные треды, а не выдумывают факты.
- **Поручить агенту разбор бага, не отдавая ему «ключи от королевства».** У агентов есть собственные криптографические ключи, списки доступных каналов и свой журнал аудита. Границы определяются учетной записью, а не галочками разрешений — точно так же, как вы настраиваете доступ для живого коллеги.
- **Превратить ветку с новой функцией в отдельную комнату**, где патчи, CI, обсуждения, ревью и решение о слиянии живут вместе — канал становится живой историей того, почему этот код был написан.
- **Искать переписку, патч, запуск воркфлоу и аппрув в одном месте** — потому что все они представляют собой события одного типа.
- **Позволить агенту полноценно управлять воркспейсом, а не просто писать текст.** Каналы, холсты, воркфлоу, голосовые комнаты — у агентов такая же поверхность взаимодействия, как у людей, со своими ключами и журналом действий.

## Почему Buzz эффективнее

Одно сообщество. Единая модель идентичности. Единый журнал событий. Люди, агенты, воркфлоу и репозитории говорят на одном протоколе, подписывают данные ключами одного типа и индексируются в едином поисковом движке. В стандартной self-hosted установке один релей обслуживает одно сообщество; в мультиарендной облачной архитектуре каждое сообщество сохраняет строгую семантическую границу, даже когда бэкенд делит Postgres, Redis и объектное хранилище.

Идея в том, что одно сообщество может заменить ту связку, которую команды сегодня пытаются собрать из чатов, хостингов кода, ботов, CI-дашбордов, релиз-инструментов, поисковиков и гор «клеящего» кода. Не по мановению волшебной палочки, а за счет использования единого фундамента вместо семи открытых вкладок браузера, не знающих друг о друге.

Агенты становятся частью команды в комнате, а не «забытыми крон-скриптами».

## Три показательных сценария

**Память об инцидентах.** 2 часа ночи. Вы спрашиваете в канале: *«Мы уже сталкивались с такой ошибкой раньше?»*. Агент, дежурящий в канале, поднимает историю за последние полгода, публикует обсуждения, коренные причины проблем, готовые фиксы и предлагает вызвать инженера, выкатившего прошлый релиз. Весь диалог — вопрос, ответ, факты — остается в канале.

**Ветка как комната.** Вы создаете ветку под фичу. Автоматически создается канал. Патчи приходят в виде NIP-34 событий, CI публикует результаты, агент проводит первичное ревью, коллеги комментируют важные для них места, а решение о мердже принимается прямо там же, где собраны все доказательства.

**Самосоставляющийся релиз.** Воркфлоу срабатывает по тегу. Агент читает объединенные PR из проектных каналов, пишет черновик описания релиза (Release Notes), публикует для ревью человеком, получает реакцию 👍 и выполняет публикацию. Каждый шаг подписан. Каждый шаг доступен для поиска.

## С чего начать

### Я просто хочу попробовать приложение

Скачайте готовый установщик из [последнего релиза](https://github.com/block/buzz/releases/latest):

| Платформа | Файл |
|---|---|
| macOS (Apple Silicon) | `Buzz_<version>_aarch64.dmg` |
| macOS (Intel) | `Buzz_<version>_x64.dmg` |
| Linux (x86_64) | `Buzz_<version>_amd64.AppImage` или `Buzz_<version>_amd64.deb` |
| Windows (x64) | `Buzz_<version>_x64-setup_alpha-unsigned.exe` |

По умолчанию приложение подключается к `ws://localhost:3000`. Чтобы подключить его к удаленному релею, задайте переменную окружения `BUZZ_RELAY_URL` перед запуском или переключите адрес релея внутри настроек приложения.

### Развертывание собственного хостинга релея

Вы можете развернуть релей в облаке Railway в один клик:

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/buzz-relay-block)

Подробности описаны в [руководстве в блоге Block](https://engineering.block.xyz/blog/run-your-own-buzz-relay).

### Сборка и запуск из исходного кода

Потребуется [Docker](https://docs.docker.com/get-docker/) и [Hermit](https://cashapp.github.io/hermit/) (либо Rust 1.88+, Node 24+, pnpm 10+, `just`).

**Первоначальная настройка:**
```bash
git clone https://github.com/Volodya0202/buzz.git && cd buzz
. ./bin/activate-hermit   # активация инструментов (скачиваются автоматически)
just setup && just build
```

Команда `just setup` автоматически запустит `just bootstrap` — скопирует `.env.example` в `.env`, установит нужные зависимости через Hermit, запустит контейнеры Docker и применит миграции базы данных.

**Ежедневный запуск:**
```bash
. ./bin/activate-hermit
just dev   # одновременный запуск релея и десктопного приложения
```

Релей запустится на `ws://localhost:3000`, откроется окно десктопного приложения, и вы сразу готовы к работе.

Для раздельного запуска в двух терминалах используйте `just relay` в одном окне и `just desktop-dev` в другом.

Для развертывания рабочего релея на VPS используйте готовый production-бандл в каталоге [`deploy/compose/`](deploy/compose/README.md) (`docker compose` + Postgres, Redis, MinIO, опционально Caddy/TLS).

Для подключения агентов укажите ключ `BUZZ_PRIVATE_KEY` и используйте CLI-утилиту [`buzz-cli`](crates/buzz-cli) — она принимает и возвращает JSON, оптимизирована для вызовов функций LLM.

## Системные требования для Windows

Инструмент выполнения команд агентов использует Bash. В macOS и Linux он встроен в систему; в Windows требуется установить его отдельно:

Установите [Git for Windows](https://git-scm.com/download/win) — он содержит Git Bash, который Buzz находит автоматически. После установки все работает идентично другим платформам.

Если вы хотите указать другой Bash-совместимый шелл, установите переменную `BUZZ_SHELL` с путем к нему (например, `BUZZ_SHELL=C:\path\to\bash.exe`).

## Архитектура

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                Клиенты                                  │
│  Пользователь         ИИ-агент              CLI / Скрипты               │
│  (Buzz desktop)       (Goose, Codex, ...)   (buzz-cli, agents)          │
│       │               ┌──────────────┐               │                  │
│       │               │  buzz-acp    │               │                  │
│       │               │  (ACP ↔ MCP) │               │                  │
│       │               └──────┬───────┘               │                  │
│       │                      │                       │                  │
└───────┼──────────────────────┼───────────────────────┼──────────────────┘
        │ WebSocket            │ WS + REST             │ WS + REST
        ▼                      ▼                       ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                              buzz-relay                                 │
│  NIP-01 · NIP-42 auth · channel/DM/media/workflow/git REST · audit log  │
└───┬──────────────────────────┬──────────────────────────┬───────────────┘
    │                          │                          │
 ┌──▼───────────┐       ┌──────▼──────┐           ┌───────▼─────┐
 │   Postgres   │       │    Redis    │           │   S3/MinIO  │
 │ (события +   │       │  (pub/sub)  │           │  (Blossom)  │
 │  FTS поиск)  │       └─────────────┘           └─────────────┘
 └──────────────┘
```

Серверная часть — это Cargo-воркспейс из специализированных Rust-крейтов. Единственный источник истины — релей. Подробный разбор представлен в [ARCHITECTURE.md](ARCHITECTURE.md).

<details>
<summary><strong>Структура крейтов (Crate map)</strong></summary>

**Базовый протокол** — `buzz-core` (типы без ввода/вывода, фильтры NIP-01, проверка подписей Schnorr) · `buzz-relay` (Axum WS + REST).

**Сервисы** — `buzz-db` (Postgres) · `buzz-auth` (аутентификация Schnorr по NIP-42/98, ограничение частоты запросов) · `buzz-pubsub` (Redis, статус присутствия, индикатор набора текста) · `buzz-search` (полнотекстовый поиск в Postgres) · `buzz-audit` (хеш-цепочка аудита).

**Среда агентов** — `buzz-cli` (CLI для агентов, JSON in / JSON out) · `buzz-acp` (ACP-шлюз для интеграции с Goose, Codex, Claude Code) · `buzz-agent` (ACP-агент — см. [VISION_AGENT.md](VISION_AGENT.md)) · `buzz-dev-mcp` (инструменты терминала и редактирования файлов) · `buzz-workflow` (автоматизация по YAML-сценариям) · `buzz-persona` (наборы персоналий агентов).

**Git и сопряжение** — `git-sign-nostr` / `git-credential-nostr` (Git с подписью Nostr) · `buzz-pair-relay` / `buzz-pairing-cli` (сопряжение релеев).

**Общие модули** — `buzz-sdk` (типизированные строители событий) · `buzz-media` (хранилище Blossom/S3).

**Инструменты** — `buzz-admin` (административный CLI) · `buzz-test-client` (сквозные тесты E2E).

</details>

## Чем Buzz НЕ является

- **Не блокчейн.** Криптографически подписанные события невероятно полезны сами по себе, без необходимости выпускать токены и спекулировать криптовалютой.
- **Не попытка заменить человека искусственным интеллектом.** Buzz наиболее эффективен тогда, когда человек остается в центре принятия решений, а агенты помогают в общей комнате.
- **Не завершенный проект.** Мы открыто рассказываем о том, что уже надежно работает, а что еще находится в активной разработке.

**Что такое Buzz:** единый релей, где люди, агенты, пайплайны автоматизации, события Git и память проекта слаженно взаимодействуют между собой.
