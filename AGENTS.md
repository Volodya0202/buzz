# AGENTS.md — Руководство для ИИ-агентов, участвующих в разработке

Данное руководство предназначено для ИИ-агентов, вносящих вклад в кодовую базу Buzz. В нем описан специфичный для агентов контекст и принятые соглашения. Общую информацию для контрибьюторов (настройка, стиль кода, процесс PR) см. в [CONTRIBUTING.md](CONTRIBUTING.md).

---

## Продуктовый контракт

Прежде чем планировать или проводить ревью нетривиальных изменений:

1. Прочитайте [VISION.md](VISION.md).
2. Прочитайте документы `VISION_*.md`, относящиеся к затрагиваемой функциональности.
3. Ознакомьтесь с применимыми инструкциями в [TESTING.md](TESTING.md).
4. Убедитесь, что предлагаемое решение развивает, или как минимум не противоречит, продуктовой концепции.

Текущая реализация описывает продукт сегодня; концептуальные документы описывают продукт, каким он должен стать. Локально корректное изменение может оказаться неверным, если оно идет вразрез с общим направлением развития.

## Экосистема проекта

Buzz охватывает пять репозиториев. Текущий репозиторий (`block/buzz`) — это открытый исходный код релея, десктопного и мобильного приложений, а также CLI:

| Репозиторий | Назначение |
|---|---|
| [block/buzz](https://github.com/block/buzz) | Открытый исходный код: релей, десктоп, мобильное приложение, CLI, среда агентов |
| [squareup/buzz-releases](https://github.com/squareup/buzz-releases) | Пайплайны сборки релизов для macOS и iOS |
| [squareup/sprout-oss](https://github.com/squareup/sprout-oss) | CI-пайплайн сборки Docker-образа релея |
| [squareup/block-coder-tf-stacks](https://github.com/squareup/block-coder-tf-stacks) | Terraform + ArgoCD для развертывания релея в Kubernetes |
| [squareup/sprout-backend-blox](https://github.com/squareup/sprout-backend-blox) | Провайдер бэкенда для подключения агентов Blox к релею |

## Структура репозитория

```
crates/
  # Релей и ядро
  buzz-relay          # WebSocket сервер релея — главная точка входа; хостинг git и аудио
  buzz-core           # Базовые типы, проверка подписей, сопоставление фильтров, реестр kind
  buzz-db             # Хранилище событий на Postgres и уровень доступа к данным
  buzz-auth           # Аутентификация и авторизация (NIP-42, NIP-98)
  buzz-pubsub         # Redis pub/sub fan-out, присутствие, набор текста
  buzz-search         # Полнотекстовый поиск Postgres FTS
  buzz-audit          # Хеш-цепочка неизменяемого журнала аудита
  buzz-media          # Хранилище медиа Blossom/S3

  # Среда агентов
  buzz-acp            # ACP-шлюз, связывающий события Buzz с ИИ-агентами
  buzz-agent          # Минимальный агент, совместимый с ACP
  buzz-dev-mcp        # Сервер MCP для разработчиков (инструменты терминала и файлов)
  buzz-persona        # Наборы персоналий агентов
  buzz-workflow       # Движок воркфлоу YAML-as-code

  # Клиенты и сопряжение
  buzz-pair-relay     # Эфемерный релей сопряжения устройств по NIP-AB
  buzz-pairing-cli    # CLI для тестирования сопряжения
  git-sign-nostr      # Подпись git-объектов ключом Nostr
  git-credential-nostr# Помощник учетных данных git для авторизованного push/fetch

  # Инструменты и общее
  buzz-cli            # CLI для агентов (JSON in / JSON out)
  buzz-sdk            # Строители типизированных событий Nostr
  buzz-admin          # CLI оператора для администрирования релея
  buzz-ws-client      # Общий клиент WebSocket NIP-42
  buzz-test-client    # Интеграционный тестовый клиент и набор тестов E2E
  sprig               # Монолитная сборка: ACP + агент + dev MCP

desktop/              # Десктопное приложение на Tauri 2 + React 19
web/                  # Веб-клиент браузера (просмотр репозиториев)
mobile/               # Мобильное приложение на Flutter
migrations/           # SQL-миграции (применяются при старте релея)
scripts/              # Вспомогательные скрипты разработки
.env.example          # Шаблон конфигурации окружения
```

## Начало работы

```bash
. ./bin/activate-hermit   # активация окружения hermit (Rust, Node и др.)
cp .env.example .env      # создание локальной конфигурации
just setup && just build  # подъем сервисов и сборка проекта
```

## Соглашения для агентов-разработчиков

1. **Не ломайте протокол.** Добавление новых возможностей происходит через введение новых типов `kind`.
2. **Изоляция подсистем.** Подсистемы общаются только через релей.
3. **Безопасность прежде всего.** Все входящие события обязаны проходить проверку подписи Шнорра, хеша идентификатора и прав доступа до их сохранения или рассылки.
4. **Документация.** Обновляйте архитектурную и проектную документацию при внесении изменений в ключевые интерфейсы.
