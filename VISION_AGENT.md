# Концепция: buzz-agent + buzz-dev-mcp

## Проблема

Агент для написания кода должен быть достаточно компактным, чтобы всю его структуру можно было удержать в голове. Если вы не можете отследить ошибку от симптома до первопричины за несколько минут — система слишком сложна. Если вы не можете запустить десять экземпляров параллельно, не опасаясь за ресурсы — система слишком тяжеловесна.

Мы создали то, что опытный инженер может прочитать за вечер и полностью понять.

## Что мы создали

Два бинарных модуля, два стандарта протоколов, никакой жесткой связанности между ними:

**buzz-agent** — это агент протокола ACP (Agent Client Protocol). Он взаимодействует по стандартным потокам ввода/вывода (stdio) по протоколу Agent Client Protocol, вызывает LLM и использует инструменты MCP. Поддерживает несколько параллельных сессий, каждая со своими MCP-серверами, историей и контекстом. При заполнении контекста сессия сама сжимает историю и продолжает работу. Агент работает с Zed, JetBrains, buzz-acp или любым другим ACP-клиентом.

**buzz-dev-mcp** — сервер протокола MCP. Он предоставляет любому агенту терминал (shell) и редактор файлов. Эфемерные процессы с гарантированным завершением групп процессов на любом пути выхода. Ограниченный размер вывода. Редактирование файлов строго относительно рабочей директории.

Вместе: два Rust-крейта, созданных специально для автономной headless-разработки.

## Архитектура

```
Любой ACP-клиент (Zed, JetBrains, buzz-acp, собственный клиент)
        |
        | stdio ACP (JSON-RPC 2.0)
        v
  buzz-agent (до 8 параллельных сессий)
        |
        | stdio MCP (JSON-RPC 2.0) — по одному на сессию
        v
  buzz-dev-mcp (или любой сторонний MCP-сервер)
        |
        v
  shell, str_replace, todo; rg + tree в PATH
```

## Принципы проектирования

- **Минимализм.** Если что-то можно удалить — удалите; если код остается, он должен окупаться производительностью, безопасностью или ясностью.
- **Надежность.** Никакого `unsafe`. Никаких паник. Ограниченное время жизни процессов, ограниченный размер вывода, ограниченная история. Гарантированное завершение группы процессов при любом выходе.
- **Стандарты вместо кастомных решений.** ACP — единственный интерфейс к агенту. MCP — единственный интерфейс к инструментам. Никакого общего разделяемого состояния во время выполнения.
- **Честность.** Агент — это простой и надежный цикл: запрос к LLM, выполнение вызовов инструментов, повтор.
