# Тестирование Buzz

## Автоматизированные тесты

```bash
just test-unit          # Модульные тесты — внешняя инфраструктура не требуется
just test               # Модульные + интеграционные тесты (Docker поднимается при необходимости)
```

Команда `just test` запускает модульные тесты и интеграционные тесты с реальными экземплярами Postgres и Redis (запускаемыми автоматически). Сквозные тесты (E2E) в крейте `buzz-test-client` помечены как `#[ignore]` и требуют предварительно запущенного релея:

```bash
# Сначала запустите релей в отдельном окне, затем:
cargo test -p buzz-test-client -- --ignored
```

---

## Стандарты тестирования

1. **Регрессионные тесты должны тестировать реальные пути исполнения кода.** Защитный код, удаление которого не приводит к падению ни одного теста, ни от чего не защищает.
2. **Чистые предикаты тестируются табличными тестами** по всей матрице входных значений.
3. **Локаторы Playwright должны быть строго ограничены областью (scoped)** во избежание флакающих тестов в strict-mode.

---

## Запуск локального тестового релея

Самый быстрый способ протестировать работу релея от начала до конца — собрать релизные бинарники, запустить `buzz-relay` и протестировать его через `buzz-cli`:

### 1. Подготовка

```bash
. ./bin/activate-hermit          # активация инструментария
just bootstrap                   # генерация .env и стабильных ключей
just setup                       # запуск сервисов Docker и применение миграций
```

> ⚠️ `just reset` полностью удаляет локальные данные БД и пересоздает схему с нуля.

### 2. Сборка бинарников

```bash
cargo build --release -p buzz-relay -p buzz-cli -p buzz-admin
export PATH="$PWD/target/release:$PATH"
```

### 3. Запуск релея

В отдельном терминале:

```bash
set -o allexport
source .env
set +o allexport
buzz-relay                     # запускается на ws://localhost:3000
```

Проверка доступности релея:

```bash
curl http://localhost:3000/health
```
